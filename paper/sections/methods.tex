\section{Problem formulation and evaluation protocol}
\label{sec:methods}

This section defines the supervised forward-emulation problem and the evaluation protocol used throughout the benchmark. The data-generation details are described in Section~\ref{sec:data-generation}; the model architectures and optimization choices are described separately in Sections~\ref{sec:models} and~\ref{sec:training}. Here, the emphasis is on the mathematical object being learned, the numerical references that define the labels, and the metrics used to decide whether a surrogate is accurate, fast, robust, and scientifically interpretable.

\subsection{Forward emulation task}
\label{subsec:forward-task}
Let $\Omega=[0, 1]^2$ denote the normalized two-dimensional computational domain and let $[H, W]$ be the grid resolution. Each scenario contains a bathymetry field $b\in\mathbb{R}^{H \times W}$, an initial-surface displacement $q \in\mathbb{R}^{H \times W}$, and an initial water-depth field $h_0 \in\mathbb{R}^{H \times W}$. The bathymetry convention is
\[
b(x, y) < 0 \quad \text {for submerged cells},
\]
so the still-water depth used by the data generator is
\[
h_{\mathrm{rest}}(x, y) = \max(-b(x, y) + \eta_{\mathrm{sea}},\, 0),
\]
where $\eta_{\mathrm{sea}}$ is the configured sea-level offset. The sampled source-strength multiplier $a$ converts the raw source field into the initial free-surface displacement
\[
\eta_0(x, y) = a\, q(x, y),
\]
and the shallow-water initial depth is clipped to remain non-negative,
\[
h_0(x, y) = \max(h_{\mathrm{rest}}(x, y) + \eta_0(x, y),\, 0).
\]
The stored initial free surface is therefore $h_0 + b$, which equals $\eta_0$ away from the clipping region.

The default supervised input tensor stacks the active spatial channels
\[
X = [\,b,\, q,\, h_0\,] \in\mathbb{R}^{C \times H \times W},
\]
with C = 3 for the main single-solver experiments. The preprocessing code also supports optional initial-surface and solver-identity channels, but these are not part of the default single-reference FNO configuration. For a numerical reference solver $s$, the target is a future free-surface trajectory
\[
Y_s = [\,\eta_s(t_1),\, \eta_s(t_2),\, \ldots,\, \eta_s(t_T)\,] \in\mathbb{R}^{T \times H \times W}.
\]
The initially stored frame is not used as a prediction target. With the default rollout settings the solver is advanced for $250$ updates and stores states with solver-step indices $0, 5, 10, \ldots, 250$, giving $51$ saved frames per rollout. For the adaptive-CFL shallow-water references, these saved frames are indexed rollout snapshots with recorded timestamps, not values interpolated onto a shared physical-time grid. Preprocessing then discards the initial frame and keeps $T = 50$ future frames as the multi-step forecast target.

A surrogate model $f_\theta$ is trained to approximate the solver-conditioned operator
\[
f_\theta : X \mapsto \widehat{Y}_s \approx{Y_s}
\]

The labels are produced by three numerical references on the same scenario design: a hydrostatic-reconstruction finite-volume solver, a MUSCL-HR finite-volume solver, and a Boussinesq-type weakly dispersive solver. Hydrostatic reconstruction is the primary reference used to anchor the benchmark, while MUSCL-HR and Boussinesq are comparison references with different numerical assumptions. The Boussinesq solver evolves the free surface directly, so its target $\eta$ is read from the surface state rather than reconstructed from depth; the supervised input, however, uses the same $C=3$ channel stack in the current pipeline.

\subsection{Numerical reference formulation}
\label{subsec:numerical-reference-formulation}

The shallow-water references evolve the conservative state
\[
U = [\,h,\, hu,\, hv\,]^\top,
\]
where $h$ is the water depth and $(hu, hv)$ are the depth-integrated momenta. The free surface is reconstructed as
\[
\eta = h + b.
\]
Ignoring the boundary terms, the two-dimensional shallow-water equations with bathymetry source terms can be written as
\[
\partial_t U + \partial_x F(U) + \partial_y G(U) = S(U, b),
\]
with fluxes
\[
F(U) = 
\begin{bmatrix}
    hu \\[2pt]
    \dfrac{(hu) ^ 2}{h} + \dfrac{1}{2}gh ^ 2 \\[6pt]
    \dfrac{hu\, hv}{h}    
\end{bmatrix},
\qquad
G(U) =
\begin{bmatrix}
    hv \\[2pt]
    \dfrac{hu\, hv}{h} \\[6pt]
    \dfrac{(hv) ^ 2}{h} + \dfrac{1}{2}gh ^ 2
\end{bmatrix},
\]
and the bathymetry source term
\[
S(U, b) =
\begin{bmatrix}
    0 \\
    -gh\, \partial_x b \\
    -gh\, \partial_y b
\end{bmatrix}.
\]
In the implementation the divisions by $h$ use dry-cell protection and momentum clipping, to avoid numerical overflow near the nearly dry cells.

Both shallow-water references use finite-volume updates of the form
\[
U_{i, j} ^ {\,n + 1} = U_{i, j} ^ {\,n}
- \frac{\Delta t}{\Delta x} \left(\mathcal{F}_{i + 1/2,\, j} - \mathcal{F}_{i - 1/2,\, j}\right)
- \frac{\Delta t}{\Delta y} \left(\mathcal{G}_{i,\, j + 1/2} - \mathcal{G}_{i,\, j - 1/2}\right)
+ \Delta t\, S_{i, j},
\]
where $\mathcal{F}$ and $\mathcal{G}$ are the numerical interface fluxes. The base interface flux is a Rusanov flux,
\[
\mathcal{F}(U_L, U_R) = \frac{1}{2}\left(F(U_L) + F(U_R)\right) - \frac{1}{2}\,\alpha_x\left(U_R - U_L\right),
\]
with local wave-speed estimate
\[
\alpha_x = \max\!\left(|u_L| + \sqrt{g h_L},\; |u_R| + \sqrt{g h_R}\right),
\]
and an equivalent $y$-direction speed using $v$. This choice is diffusive compared with sharper Riemann solvers, but it is robust and suitable for controlled dataset generation \citep{toro2009riemann,toro2026rusanov}.

Because the scheme is explicit, the time step is not free: an explicit finite-volume update is only stable when the information does not travel more than one cell per step, which is the Courant--Friedrichs--Lewy (CFL) condition. We therefore do not fix $\Delta t$ in advance but choose it adaptively at every step from the current state, using the same characteristic speed $|U| + \sqrt{gh}$ that appears in the Rusanov flux,
\[
\Delta t = \mathrm{CFL} \cdot \left[\,\max \! \left(\frac{\max(|u| + \sqrt{gh})}{\Delta x},\; \frac{\max(|v| +  \sqrt{gh})}{\Delta y} \right) \right] ^ {-1},
\]
where the maxima are taken over the whole grid and the target CFL number is $\mathrm{CFL} = 0.45$ in the default configuration. Adapting $\Delta t$ this way keeps the rollout stable when a large initial displacement temporarily increases the wave speed, while still taking the largest safe step elsewhere; this matters for a benchmark, because an over-large fixed step would let unstable samples enter the training labels.

The hydrostatic-reconstruction solver modifies the left and right water depths at each face before computing the Rusanov flux. For an interface with bed elevations $b_L$ and $b_R$, it sets
\[
z ^ \star = \max(b_L, b_R), \qquad
h_L ^ \star = \max(0,\, h_L + b_L - z ^ \star), \qquad
h_R ^ \star = \max(0,\, h_R + b_R - z ^ \star).
\]
These reconstructed states preserve nonnegative water depth and help to balance the flux-gradient and bed-slope terms for stationary water over uneven bathymetry \citep{audusse2004hydrostatic}. In this well-balanced formulation the bathymetry source $S$ is absorbed into the reconstructed face fluxes rather than added as a separate term, so the $\Delta t\, S_{i, j}$ contribution above is schematic for the hydrostatic solver; the MUSCL-HR solver instead applies an explicit, centered discretization of the same source after its slope-limited reconstruction. The MUSCL-HR solver uses the same hydrostatic face idea but reconstructs $h$, $\eta$, $u$ and $v$ with minmod-limited slopes before face update, followed by a two-state Heun update. This gives a less diffusive second-order comparison reference while retaining the lake-at-rest safeguards needed for tsunami-like bathymetry \citep{clain2016secondorder, hou2015muscl}.

The third numerical reference is a Boussinesq-type comparison solver. We include it because the shallow-water equations above are non-dispersive: all long waves travel according to the local depth-dependent speed, but the model does not represent the weak frequency dispersion that can matter for shorter components of a tsunami-like disturbance. The implementation is not a full nonlinear coastal Boussinesq model. It is an elevation-only, linear, weakly dispersive approximation used as an additional reference beside Hydrostatic and MUSCL-HR.

In the variable-depth mode used here, the unknown is the free-surface elevation $\eta$ and its time derivative $\eta_t$. If the dispersive correction is removed, the model reduces to the familiar linear long-wave surface equation
\[
\eta_{tt} = g\, \nabla \cdot(H \nabla \eta),
\]
where $H$ is the still-water depth. The implemented Boussinesq form modifies this by solving for the acceleration $a_\eta = \eta_{tt}$ through a Helmholtz-type linear system,
\[
\left(I - \alpha_B\, \nabla \cdot(H ^ 2 \nabla)\right) a_\eta = g\, \nabla \cdot(H \nabla \eta),
\]
where
\[
H(x, y) = \max\!\left((-b(x, y) + \eta_{\mathrm{sea}})\, s_H,\; H_{\min}\right)
\]
is the effective depth used inside this solver. The factor $s_H$ is an implementation parameter used only for auxiliary diagnostics; in the shared dataset reported here, we use $s_H = 1$. The lower bound $H_{\min}$ prevents zero or near-zero depth from making the operator singular or badly conditioned. In the main configuration $H_{\min} = 10^{-4}$, $\alpha_B = 1/3$, and the same normalized bathymetry convention as the shallow-water solvers is used.

The coefficient $\alpha_B$ controls the strength of the weakly dispersive correction. When $\alpha_B = 0$, the left hand side becomes just $a_\eta$, so the update is just the non-dispersive linear long-wave equation written above. A positive $\alpha_B$ makes the acceleration depend on a spatial solve involving $H ^ 2 \nabla a_\eta$, which is the part that gives this reference its weakly dispersive character. We set $\alpha_B = 1/3$, matching the solver default, and treat it as a fixed model choice rather than a fitted physical parameter. The linear system is applied matrix-free and solved with conjugate gradients, so the implementation never forms a dense matrix; the rollout is then advanced with a velocity-Verlet step, which updates $\eta$ and $\eta_t$ using accelerations at the start and end of the step. This gives the benchmark a weakly dispersive comparison reference beside the two shallow-water references, while still keeping Hydrostatic as the main solver and without treating any numerical reference as real-ocean truth.

\subsection{Reference-solver health and consistency checks}
\label{subsec:reference-validation}

As health and consistency checks for the reference solvers used for dataset generation, we run a small series of numerical tests before generation. These checks screen for basic implementation failures and unstable labels; they are not substitutes for grid/time-step convergence studies, independent solver benchmarks, or event-scale validation against observations.

\paragraph{Lake at rest.} A well-balanced shallow-water solver should preserve a stationary free surface over non-uniform bathymetry. We therefore initialize a fully submerged, spatially varying bathymetry with zero surface elevation, $\eta_0(x,y) = 0$, and zero momentum, $hu(x,y) = hv(x,y) = 0$. Since $\eta = h + b$, this corresponds to an initial water depth $h_0(x,y) = -b(x,y)$. Both the hydrostatic and MUSCL-HR solver are advanced for many adaptive-CFL time steps with the sponge damping disabled. We consider the lake-at-rest condition preserved when the maximum free-surface drift stays below $10^{-8}$ and the maximum absolute momentum stays below $10^{-7}$. This property matters over long rollouts, because a solver that slowly drifts from rest would inject a spurious signal into every training label.

\paragraph{Dynamic finite-state behavior.} Lake at rest only checks the trivial equilibrium, so we additionally run dynamic rollouts from non-trivial initial displacements and confirm that the state remains finite and bounded over the full horizon. This guards against late time blow-up or oscillations that look stable for a few steps and then produce non-finite values near the dry cells.

\paragraph{Quality status.} During generation each rollout is screened by the quality policy, which records whether the trajectories contain non-finite values, depth below tolerance, or excessive surface amplitude and velocity. For the Boussinesq solver, the same health record also checks the free-surface-to-depth ratio and whether the conjugate-gradient acceleration solve converged. The outcome is written into the per-sample metadata as a quality status. This status also makes accepted samples explicitly identifiable during dataset construction, avoiding unnecessary recomputation.

\subsection{Evaluation metrics}
\label{subsec:eval-metrics}

For field accuracy, we report the mean absolute error (MAE), root-mean-squared error, the relative $L2$ error, and maximum absolute error over the predicted trajectory. Writing  $y$ for the reference frames and $\widehat{y}$ for the prediction, and letting $k$ index all elements of the $T \times H \times W$ trajectory tensor with $N$ entries in total,
\[
\mathrm{MAE} = \frac{1}{N}\sum_{k} \lvert \widehat{y}_k - y_k \rvert,
\qquad
\mathrm{RMSE} = \sqrt{\frac{1}{N}\sum_{k} (\widehat{y}_k - y_k)^2},
\]
\[
\mathrm{rel}\,L_2 = \frac{\lVert \widehat{y} - y \rVert_2}{\lVert y \rVert_2},
\qquad
\mathrm{max\text{-}err} = \max_{k} \lvert \widehat{y}_k - y_k \rvert .
\]

Unless otherwise stated the denormalized benchmark-scale metrics are computed after reversing the target normalization, so that the errors are reported in the same stored scale as $\eta$. The maximum absolute error is also a useful proxy for local worst-case behavior and for time-stepping stability.

When we aggregate these metrics over a whole evaluation split, we accumulate the underlying sums across every sample first and only reduce at the end, instead of averaging the per-batch numbers. Concretely we keep a running total of $\sum_k \lvert \widehat{y}_k - y_k \rvert$, $\sum_k (\widehat{y}_k - y_k) ^ 2$, and $\sum_k y_k ^ 2$ over the full split, and track a single running maximum for max-err. This matters because the relative $L_2$ is a ratio of norms and the max-err is a maximum, so averaging them batch-by-batch would not give the true split-level value: a batch-averaged max-err in particular only reports the mean of the per-batch maxima and therefore understates the real worst case. Computing them from the accumulated sums means the reported rel\, $L_2$ and max-err are the genuine dataset-level quantities, and they no longer depend on the batch size used at evaluation time.

For distribution-shift evaluation the metrics are computed per sample first and then grouped by metadata, using the source type, the bathymetry type, the source-strength range, or the reference solver. Computing per-sample errors before grouping avoids letting a few large scenarios dominate a suite average. Note that this is deliberately a different aggregation from the split-level accumulation described above: here the relative $L_2$ and max-err of a group are the mean of the per-sample values, not a single global ratio or global maximum, so the two kinds of table should not be compared cell-for-cell. In addition to the field metrics above, we report a set of frequency-band and conserved-quantity diagnostics in the appendix, following the metric design of PDEBench \citep{takamoto2022pdebench}; these are useful for separating low and high-wavenumber error, which is relevant when the surrogate is a spectral operator.

\subsection{Generalization and resolution-transfer protocol}
\label{subsec:generalization-protocol}

The metadata-filtered suites whose composition is described in Section~\ref{sec:data-generation} are evaluated under a fixed protocol. For each suite we score the trained checkpoint on the held-out samples using the same per-sample-then-grouped metrics as above, so that an in-distribution number and an out-of-distribution number are always produced by the identical pipeline and differ only in the scenarios that are included. We distinguish two cases that are easy to conflate. A \emph{difficult-subgroup} test keeps a family in the training distribution but reports the error on a metadata-selected subset of the test pool, while a \emph{held-out-family} test removes that family from the training split entirely before preprocessing and only then evaluates it. We label each suite by which of the two it is, because only the second is evidence of generalization to an unseen family.

For resolution transfer we keep two settings separate. The \emph{proxy} setting resizes the $64 \times 64$ test fields to a target grid and evaluates the same checkpoint on the resized inputs; it is a cheap diagnostic and does not involve any new simulation. The \emph{native} setting instead evaluates the checkpoint on data that were independently generated and simulated at $32 \times 32$ and $128 \times 128$, which is the stronger test because the wavefield at each resolution is physically resolved rather than interpolated. Cross-resolution comparison is only meaningful when the target normalization is controlled, so we adopt a strict policy: a native-resolution suite is accepted only when its target normalization statistics match the reference statistics of the training distribution, and a transfer claim that mixes incompatible statistics is rejected rather than silently reported. This prevents a change of feature scaling from being mistaken for genuine resolution generalization.

\subsection{Runtime benchmarking}
\label{subsec:runtime}

The numerical reference solvers are timed using their CPU NumPy rollout implementations, excluding the bathymetry and source generation, so the denominator reflects only the forward integration. The neural surrogate is timed on CPU and, when available, the GPU. For every measurement we record the device, the batch size, the numerical precision label, and the TF32 back-end state, and on GPU we synchronize the device before and after timing so that asynchronous kernel launches are not counted as zero. Each configuration uses a short warmup and is then repeated several times, and we report the per-sample time and throughput in samples per second. The speedup is computed as
\[
\mathrm{speedup} =
\frac{\text{reference-solver rollout time per sample}}
    {\text{surrogate inference time per sample}}.
\]

We stress that these speedups are implementation-level comparisons under the reported hardware, and not universal comparisons against optimized production-grade tsunami solvers. The CPU NumPy references are reproducible and easy to audit, but they are not tuned for speed, so the numbers should be read as a relative indication and not as an absolute performance claim.

\subsection{Cross-solver and emulator-superiority analysis}
\label{subsec:cross-solver}

Because the training solver is not itself the ground truth, we separate two different quantities. The first is the raw solver-vs-solver gap, that is the denormalized benchmark-scale difference between two numerical references evaluated on the same shared scenarios. The second is the surrogate error of a model trained on one reference and compared against another. Keeping these apart is important, since a surrogate can look poor only because the two reference solvers themselves disagree.

Following the neural emulator-superiority idea \citep{koehler2026emulator}, we also report a ratio that compares a surrogate trained on reference $A$ against a second reference $B$.
\[
\rho =
\frac{\operatorname{Err}\!\left(f_\theta ^ {A},\; \mathrm{ref}\,B \right)}
     {\operatorname{Err}\!\left(\mathrm{ref}\, A,\; \mathrm{ref}\,B \right)},
\]
where the error is a denormalized benchmark-scale metric evaluated on the same scenarios with separate denormalization for the prediction and target. A value $\rho < 1$ would mean that the emulator trained on $A$ is in fact closer to $B$ than its own training solver $A$ is. We only report this ratio when the prediction and target denormalization, and the input normalization statistics, are compatible, because otherwise the scale comparison is not meaningful. The hydrostatic, MUSCL-HR, and Boussinesq references are generated on the same scenario IDs, so raw solver-vs-solver field gaps can be computed for all pairs. The emulator-superiority ratio is treated as a main result for the hydrostatic/MUSCL-HR pair because those are the two shallow-water references; Boussinesq is reported as the weakly dispersive comparison baseline for the same benchmark.

\subsection{Uncertainty quantification}
\label{subsec:uncertainty}

Point accuracy alone does not tell a user when a surrogate is likely to be wrong, which matters for any hazard-oriented application. We therefore estimate predictive uncertainty with a deep ensemble of $M$ independently trained models that differ only in their random seed \citep{lakshminarayanan2017deepensembles}. For an input $X$ the members produce predictions $\{\widehat{Y} ^ {(m)}\}_{m = 1} ^ {M}$, and we form the ensemble mean and the per element predictive variance
\[
\bar{Y} = \frac{1}{M}\sum_{m = 1} ^ {M}\widehat{Y} ^ {(m)},
\qquad
\sigma ^ 2 = \frac{1}{M}\sum_{m = 1} ^ {M}\left(\widehat{Y} ^ {(m)} - \bar{Y}\right) ^ 2
\]
where $\bar{Y}$ is used as a prediction and $\sigma$ as the uncertainty. A single member gives a degenerate zero variance, so we require $M \ge 2$ and use $M = 7$ in the reported experiment.

We assess the quality of this uncertainty in two ways. First, we measure whether the uncertainty tracks the actual error through the Pearson correlation between the per-element predictive standard deviation $\sigma$ and the absolute error $\lvert \bar{Y} - Y \rvert$; a useful uncertainty should be larger where the error is larger. Second, we check calibration by treating each prediction as Gaussian with mean $\bar{Y}$ and standard deviation $\sigma$ and measuring the empirical coverage of central prediction intervals at several nominal levels, together with the Gaussian negative log-likelihood. A well-calibrated model should have an empirical coverage close to the nominal level, for example about $90\%$ of targets inside the nominal $90\%$ interval. We additionally report these uncertainty metrics on the distribution-shift suites of Section~\ref{subsec:eval-metrics}, since a trustworthy uncertainty should grow under distribution shift rather than stay falsely confident. We interpret these as reliability diagnostics and do not claim formally calibrated risk.
